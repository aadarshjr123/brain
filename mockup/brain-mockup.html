How the real build would work

Shape of the data

Everything on this page is three JSON-ish lists: nodes (browser parts, grouped), actions (frontend things you do) and each action's ordered trace. The map, the trace panel, the pipeline strip and the recall quiz are all projections of the same data. Adding a concept means adding one action object, no new UI.

Rendering

2D here is plain SVG, which is enough up to a few hundred nodes. The 3D view is a straight port of the same positions to three.js: nodes become spheres, edges become line segments, the trace becomes a moving light. In the real build that lives in React Three Fiber with an on-demand frame loop so nothing renders while you read.

Performance budget

  • Instanced meshes for nodes, one BufferGeometry for all edges, labels as SDF text (troika) not DOM.
  • Frame loop on demand. Animate the trace with a clock, resume rendering only during a trace or orbit.
  • Three.js chunk lazy-loaded. The 2D map is the default and ships first, so the page is useful before WebGL arrives.
  • Never touch React state per frame. Mutate refs inside useFrame.
  • Pause the loop when the tab is hidden or the canvas scrolls out of view.

Why a recall mode

You said this is for coming back to relearn. Looking at a map is recognition, not recall. The quiz tab asks you to predict the trace before it is shown, which is what makes it stick.
